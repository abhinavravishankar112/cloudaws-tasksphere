--------------------------------------------------------------------------------
[Visual / Screen Action]

[Voiceover / Audio Script]
"Let's start by taking a look at the core codebase structure inside the src directory. We follow a strict multi-tiered layered architecture separating concerns into routes, controllers, business services, and database access logic.

In app.js, we configure security middleware, CORS, rate-limiting, and express-validator for strict payload validation. Requests are authenticated using JWT tokens validated by custom auth middleware on protected endpoints.

We have also integrated interactive Swagger/OpenAPI documentation, allowing client developers to test API endpoints seamlessly."


--------------------------------------------------------------------------------
SCENE 3: DATABASE MODELING WITH PRISMA & POSTGRESQL (1:50 - 2:30)
--------------------------------------------------------------------------------
[Visual / Screen Action]
- Open prisma/schema.prisma.
- Highlight User and Task models.
- Point to TaskPriority and TaskStatus enums, plus @@index definitions.

[Voiceover / Audio Script]
"For persistent data storage, we utilize PostgreSQL paired with Prisma ORM. Here in our Prisma schema, we define two main entities: User and Task.

Tasks support custom enums for priority (from LOW to URGENT) and status (from TODO to DONE). Notice our database indexing strategies on userId, status, priority, and dueDate to ensure rapid lookup performance even under high traffic."


--------------------------------------------------------------------------------
SCENE 4: CONTAINERIZATION & LOCAL STACK (2:30 - 3:15)
--------------------------------------------------------------------------------
[Visual / Screen Action]
- Open Dockerfile in VS Code.
- Highlight multi-stage build: node:20-alpine AS deps, AS builder, AS runner.
- Point out non-root user creation: USER nodejs.
- Open docker-compose.yml and run `docker compose up` in terminal.

[Voiceover / Audio Script]
"Moving to containerization, we wrote an optimized multi-stage Dockerfile. By separating dependency resolution, Prisma client generation, and final execution, we produce ultra-lightweight Alpine images. For security compliance, the container executes under a non-root nodejs user context.

For local development, running `docker compose up` provisions both the API container and a PostgreSQL database with health checks configured out of the box."


--------------------------------------------------------------------------------
SCENE 5: CLOUD INFRASTRUCTURE WITH TERRAFORM (3:15 - 4:00)
--------------------------------------------------------------------------------
[Visual / Screen Action]
- Open terraform/main.tf in VS Code.
- Highlight aws_instance resource, security groups (ports 22, 80, 443, 3000), and Elastic IP.
- Show user-data.sh.tpl script.

[Voiceover / Audio Script]
"To deploy this to the cloud predictably, we use Infrastructure as Code via Terraform. In terraform/main.tf, we provision an AWS EC2 instance, construct VPC security groups for ports 22, 80, 443, and 3000, and configure elastic IPs.

Our cloud-init user-data script automatically bootstraps the instance upon provisioning—installing Docker, Nginx reverse proxy, and system dependencies."


--------------------------------------------------------------------------------
SCENE 6: CONTAINER ORCHESTRATION WITH KUBERNETES (4:00 - 4:45)
--------------------------------------------------------------------------------
[Visual / Screen Action]
- Open k8s/ folder showing deployment.yaml, service.yaml, ingress.yaml, and hpa.yaml.
- Highlight livenessProbe and readinessProbe in deployment.yaml.
- Highlight horizontal autoscaling rules in hpa.yaml.

[Voiceover / Audio Script]
"In addition to single-server VM deployments, we have authored Kubernetes manifests inside the k8s directory. This includes zero-downtime deployments with liveness and readiness probes pointing to /api/v1/health.

We have also configured horizontal pod autoscaling in hpa.yaml to dynamically scale pods from 2 up to 10 replicas based on CPU and memory utilization thresholds."

Once tests pass, it builds the production Docker image and safely deploys updates to our AWS EC2 server over SSH using encrypted secrets."
